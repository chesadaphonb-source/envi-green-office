# เว็บทดสอบ SIT และเว็บใช้งานจริง PRD

| ระบบ | ที่อยู่ | โค้ดต้นทาง |
| --- | --- | --- |
| PRD — ใช้งานจริง | https://chesadaphonb-source.github.io/envi-green-office/ | สาขา `main` |
| SIT — ทดลองฟังก์ชันใหม่ | https://chesadaphonb-source.github.io/envi-green-office/sit/ | สาขา `sit` |

SIT มีแถบสีเหลืองบอกว่าเป็นเว็บทดสอบและลิงก์กลับ PRD ทุกหน้า ฟังก์ชันใหม่ลงสาขา `sit` ก่อน เมื่อผู้ดูแลตรวจและอนุมัติแล้วจึงรวมการเปลี่ยนแปลงเข้า `main` เพื่อใช้งานจริง ห้าม push โค้ดหน้าจอที่ยังไม่ผ่านการรับรองเข้า `main`

ทั้งสองเว็บใช้ GitHub Pages deployment เดียว โดย workflow checkout `main` กับ `sit` คนละโฟลเดอร์ ทดสอบทั้งสองชุด แล้ววางไฟล์ PRD ไว้ที่รากและ SIT ไว้ใน `/sit/` การ push เข้า `sit` จึงไม่เปลี่ยนโค้ดหน้าจอ PRD แต่มีการสร้างและเผยแพร่ artifact ร่วมกัน หากชุดใดทดสอบหรือสร้างไม่ผ่าน จะไม่มีการเผยแพร่ทั้งชุด และเว็บรุ่นก่อนยังทำงาน

ทั้งสองเว็บอ่านสารบัญสาธารณะชุดเดียวกันและเปิดไฟล์ Drive ตามสิทธิ์เดิม ไม่มีการเขียนข้อมูลกลับ Drive หรือ Sheet จากหน้าเว็บ นี่คือการแยกโค้ดและ URL สำหรับทดสอบหน้าจอ ยังไม่ใช่การแยกฐานข้อมูลหรือระบบโฮสต์โดยสมบูรณ์ หากเพิ่มงานแก้ไขข้อมูลภายหลัง ต้องจัดชุดข้อมูลทดสอบและสิทธิ์แยกก่อน

SIT เปิดผ่านลิงก์ได้สาธารณะเหมือน PRD มี `noindex,nofollow` เพื่อลดการปรากฏในผลค้นหา ซึ่งไม่ใช่การจำกัดสิทธิ์เข้าถึง จึงใช้เฉพาะข้อมูลที่เผยแพร่ได้แล้ว

## รอบทดลองแรก

ใน SIT เพิ่มตัวกรองโฟลเดอร์/PDF/รูปภาพ/Word/ไฟล์อื่น การเรียงตามชื่อ วันที่แก้ไข และประเภทไฟล์ พร้อมจำนวนรายการแต่ละประเภทและวันที่แก้ไขล่าสุดของรายการในโฟลเดอร์หรือผลค้นหา ตัวกรองและการเรียงทำกับรายการทั้งหมดก่อนแบ่งหน้า จึงค้นพบไฟล์ที่อยู่หลังหน้าแรกได้

วันที่ “รายการทั้งหมดแก้ไขล่าสุด” เป็นวันที่แก้ไขไฟล์หรือโฟลเดอร์ ส่วน “สารบัญปรับปรุงล่าสุด” เป็นเวลาที่ระบบสแกนข้อมูลครบ การเลือกตัวกรองไม่สั่งสแกน Drive เพิ่ม

## วิธีนำขึ้น PRD

1. ตรวจหน้าแรก หมวด โฟลเดอร์ ค้นหา และเปิด PDF/รูปบน SIT รวมถึงหน้าจอมือถือ
2. เมื่อตกลงรับรุ่นแล้ว ให้รวมสาขา `sit` เข้า `main` ผ่าน pull request ที่ตรวจโค้ดและทดสอบผ่าน
3. รอ workflow `Publish Green Office` ผ่าน แล้วตรวจลิงก์ PRD
4. เมื่อต้องยกเลิกการเปลี่ยนแปลง ให้ revert commit ของรุ่นนั้นและเผยแพร่ใหม่

ไฟล์ค่าลับอยู่ใน Actions Secrets ของ repository เดิมเท่านั้น Workflow จำกัดค่าลับไว้เฉพาะขั้นดึงสารบัญและไม่ใส่ไว้ในไฟล์เว็บไซต์
