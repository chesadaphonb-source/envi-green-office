# Green Office ENVI 2569

เว็บไซต์เอกสารและหลักฐาน Green Office คณะสิ่งแวดล้อม มหาวิทยาลัยเกษตรศาสตร์

## รุ่น GitHub Pages

หน้าเว็บใหม่อยู่ใน `site/` โดยอ่านสารบัญที่โหลดครั้งเดียวสำหรับการเปลี่ยนหน้าและค้นหา ส่วน `catalog-sync/` เป็น Apps Script แยกที่จัดทำสารบัญจาก Drive ลง Google Sheet และ `.github/workflows/pages.yml` เตรียมส่งสารบัญพร้อมหน้าเว็บไปยัง GitHub Pages ไฟล์ PDF และรูปเอกสารยังเปิดจาก Drive ตามสิทธิ์เดิม

อ่าน [วิธีทดลองและเชื่อม GitHub Pages](docs/github-pages.md) และ [การตั้งค่า Apps Script จัดทำสารบัญ](catalog-sync/README.md) โค้ดเตรียมไว้ในเครื่องแล้ว ยังต้องเชื่อม repository, Sheet และโปรเจกต์จัดทำสารบัญก่อนใช้งานจริง

```powershell
npm.cmd test
npm.cmd run preview:build
npm.cmd run preview -- --base /green-office-envi/
```

การทดลองนี้แสดงหน้าเว็บพร้อมสถานะว่ายังไม่มีสารบัญ ไม่มีข้อมูลเอกสารจำลอง พื้นที่กราฟพลังงานยังเว้นว่างตามที่กำหนด

## เว็บ Apps Script เดิม

ไฟล์ในรากโครงการยังเป็นเว็บ Apps Script ที่ใช้งานอยู่และเก็บไว้ระหว่างการย้าย คำอธิบายส่วนถัดไปใช้กับเว็บเดิม ซึ่งอ่าน Google Drive โดยตรง ไม่มีฐานข้อมูล Google Sheet และไม่มีระบบ Login ของแอป อย่านำ `site/` หรือ `catalog-sync/` ไปอัปโหลดทับโปรเจกต์เว็บเดิม

การเข้าโฟลเดอร์โหลดเฉพาะชั้นที่เปิดอยู่ และเปิดต่อได้หลายชั้น ส่วนการค้นหาชื่อไฟล์และชื่อโฟลเดอร์จะไล่โครงสร้างทุกชั้นใน 7 หมวด แบ่งงานเป็นช่วงและมีปุ่มให้ค้นหาต่อจนจบ หากยังค้นหาไม่ครบ หน้าจอจะแจ้งชัดเจนว่าเป็นผลลัพธ์บางส่วน

เว็บใช้ธีมธรรมชาติตามภาพอ้างอิง พื้นฟ้าอ่อนและเขียวอ่อน เมนูด้านซ้าย และแบนเนอร์ภาพวาดอาคารคณะจาก PNG ที่ผู้ใช้ส่งมา โดยคงพื้นที่อ่านเอกสารสีขาวและหัวข้อขนาดใหญ่ ภาพหน้าแรกแสดงเต็มตามสัดส่วนเดิม ไม่ตัดภาพหรือดัดแปลงไฟล์ต้นฉบับ หน้าแรกเลือกหมวดจากเมนูด้านซ้ายเพียงแห่งเดียว และเว้นกรอบว่างใต้หัวข้อ “การใช้พลังงาน” สำหรับใส่กราฟภายหลัง โดยยังไม่มีกราฟหรือข้อมูลจำลอง

นำสัตว์เคลื่อนไหว แถบสวนเดิม ปุ่มควบคุม และโค้ดจำค่าการเคลื่อนไหวออกแล้ว ภาพหน้าแรกเป็น PNG แบบนิ่งฝังใน `hero-image.html` ส่วนไอคอนหมวดเป็น SVG ไม่ต้องใช้บริการฝากรูปภายนอก เมนูด้านซ้ายแสดงทุกหมวดจาก Drive ใช้ลิงก์จริงและแสดงหมวดปัจจุบันด้วย `aria-current` บนหน้าจอเล็กเมนูจะอยู่ด้านบนและตัดบรรทัดได้ การเปิดลิงก์เอกสารโดยตรงโหลดเมนูแยกจากเนื้อหา หากเมนูผิดพลาดสามารถลองใหม่โดยไม่โหลดเอกสารซ้ำ

หน้าระดับหมวดมีแบนเนอร์ หมายเลข ไอคอน ข้อมูลแนะนำ และเป้าหมายตามสีหมวด ข้อมูลแนะนำเป็นคำอธิบายทั่วไป ไม่ใช่ผลประเมินหรือรายการหลักฐานที่มีอยู่จริง ชื่อหมวดยึด `CriteriaService.gs` เดิม และไม่มีการแสดงเปอร์เซ็นต์ความสำเร็จที่ยังไม่มีข้อมูลรองรับ เมื่อเข้าโฟลเดอร์ย่อยหรือเอกสารจะซ่อนส่วนแนะนำเพื่อให้พื้นที่กับหลักฐาน

พื้นกล่องทุกหน้าใช้สีขาว ได้แก่ แบนเนอร์หน้าแรก/หมวด กล่องคำอธิบายและเป้าหมาย โฟลเดอร์ เอกสาร แกลเลอรี ส่วนไฟล์ Word และเมนูด้านซ้าย สีประจำหมวดอยู่ที่หัวข้อ ไอคอน และเส้นขอบ การชี้หรือเลือกกล่องยังคงพื้นขาว โดยใช้ขอบและเส้นเน้นบอกสถานะ พื้นหลังรอบหน้าคงโทนอ่อน และสีภายในตัวไฟล์ PDF/รูปภาพเป็นไปตามต้นฉบับ

ตัวอักษรปรับเพื่ออ่านง่ายขึ้น: ข้อความหลัก 1.125rem (ปกติ 18 พิกเซล), ชื่อหมวด/เอกสาร 1.25rem (20 พิกเซล), ข้อความประกอบอย่างน้อย 1rem (16 พิกเซล) ใช้ rem เพื่อขยายตามขนาดตัวอักษรที่ผู้อ่านตั้งในเบราว์เซอร์ เพิ่มระยะบรรทัด สีข้อความประกอบเข้มขึ้น และปุ่มสูงอย่างน้อย 48 พิกเซล หัวข้อและแถบปุ่มขึ้นบรรทัดใหม่ได้ มือถือกว้างไม่เกิน 560 พิกเซลใช้กล่องหมวดแถวเดียว การปรับนี้ครอบคลุมข้อความของเว็บไซต์ ส่วนตัวอักษรภายใน PDF/รูปภาพใช้การซูมของตัวอ่าน Drive

รูปต้นฉบับสำหรับเว็บไซต์เก็บใน `assets/images/` ส่วนหัวใช้ `KU copy.jpg` ที่ผู้ใช้ให้มา โดยฝังไฟล์ต้นฉบับและแสดงตามสัดส่วนเดิม ไอคอนหมวดยังใช้ SVG แบบเส้นชุดเดียวกัน ดูขั้นตอนสร้างไฟล์โลโก้ที่ [assets/images/README.md](assets/images/README.md)

## ลิงก์แยกหน้าและการนำทาง

- หน้าแรก: URL `/exec` เดิม
- หน้าหมวดและโฟลเดอร์: `/exec?folder=FOLDER_ID`
- หน้าเอกสาร: `/exec?file=FILE_ID`
- หน้าผลการค้นหา: `/exec?q=คำค้นหา` (เข้ารหัสคำค้นหาตามรูปแบบ URL)

เมนูหมวด ชื่อโฟลเดอร์ ชื่อ PDF/รูปภาพ และ breadcrumb เป็นลิงก์จริง เปิดแท็บใหม่หรือคัดลอกที่อยู่ได้ คลิกปกติเปลี่ยน URL และหน้าโดยใช้ `google.script.history` รองรับปุ่มย้อนกลับ/เดินหน้าของเบราว์เซอร์ ส่วนการเปิด URL หรือรีเฟรชจะอ่านหน้าเริ่มต้นผ่าน `google.script.url` มีปุ่มหน้าแรก กลับโฟลเดอร์ และคัดลอกลิงก์หน้านี้ หาก Clipboard ใช้ไม่ได้จะแสดงช่องลิงก์ให้คัดลอกเอง

หน้าโฟลเดอร์ยังมีตัวอย่างเอกสารอัตโนมัติ กดชื่อไฟล์หรือ “เปิดหน้าเอกสาร” เพื่อเข้าสู่หน้าเฉพาะไฟล์ที่ส่งต่อได้ หน้าเอกสารอ่านไฟล์ตาม ID พร้อมตรวจขอบเขตโฟลเดอร์ใหม่ทุกครั้ง จึงเปิดไฟล์ที่อยู่นอกหน้ารายการแรกได้โดยไม่ต้องไล่แบ่งหน้า ลิงก์ไฟล์ที่ถูกย้ายออกจากหมวดหรือถูกลบจะแสดงข้อผิดพลาด

อ้างอิงการนำทาง: [Google Apps Script history](https://developers.google.com/apps-script/guides/html/reference/history), [Google Apps Script URL](https://developers.google.com/apps-script/guides/html/reference/url)

หน้าโฟลเดอร์แสดงรายการคู่กับตัวอ่าน PDF ในหน้าเว็บ เลือก PDF แรกในข้อมูลที่โหลดแล้วโดยอัตโนมัติ ปุ่มก่อนหน้า/ถัดไปสลับตัวอย่างในโฟลเดอร์เดิม ส่วนกล่องไฟล์และปุ่ม “เปิดหน้าเอกสาร” เปิดหน้าเฉพาะไฟล์ที่มีลิงก์ส่งต่อได้ สามารถขยายพื้นที่อ่าน และไม่โหลดตัวอ่านเดิมซ้ำเมื่อเพิ่มหน้ารายการ

โฟลเดอร์ที่โหลดพบรูปภาพตั้งแต่ 2 รูปขึ้นไป แสดงภาพเต็มความกว้างเรียงแนวตั้งในส่วน “รูปภาพในหัวข้อนี้” โดยไม่ทำรายการภาพซ้ำในแถบด้านข้าง ใช้ Drive preview และ `loading="lazy"` เพื่อทยอยโหลดใกล้จอ แต่ละรูปมีลิงก์หน้าเฉพาะรูปและเปิดต้นฉบับ รูปที่แสดงแล้วไม่โหลดใหม่เมื่อกดแสดงรายการเพิ่มเติม ถ้ามีรูปเดียวจะใช้ตัวอ่านเดี่ยวเดิม หน้าค้นหายังใช้รายการกับตัวอย่างเดี่ยวเพื่อไม่ให้ผลค้นหายาวเกินไป

เก็บต้นฉบับใน Drive ต่อได้ ไม่ต้องดาวน์โหลดมาเก็บในโปรเจกต์หรืออัปโหลดรูปซ้ำ การเปลี่ยนไฟล์ใน Drive อ่านใหม่ได้ด้วยปุ่มโหลดข้อมูลใหม่ การแสดงภาพยังอยู่ภายใต้สิทธิ์ Drive เดิม ไม่มีการใช้บัญชีเจ้าของแอปส่งเนื้อหาไฟล์ส่วนตัวออกมาแทนผู้ชม

ไฟล์ Word (.doc/.docx/.docm รวมชนิด MIME ของ Word) อยู่ใต้ปุ่มแสดงไฟล์ Word ซึ่งปิดไว้เมื่อเปิดโฟลเดอร์หรือเริ่มค้นหาใหม่ การซ่อนนี้ไม่ลบไฟล์และไม่หยุดการโหลดหน้าถัดไป ส่วน Google Docs, Sheets, Excel และไฟล์อื่นยังเปิดผ่าน Drive ได้

ตัวอ่านใช้ Drive preview ผ่าน HTTPS พร้อม resource key ของไฟล์ จึงยังขึ้นกับสิทธิ์เข้าถึงไฟล์และความสามารถในการแสดงตัวอย่างของ Drive (รวม HEIC/HEIF) หากตัวอย่างไม่แสดง มีลิงก์เปิดต้นฉบับสำรอง ไม่มีการแปลงไฟล์หรือเปลี่ยนสิทธิ์แชร์

## ความปลอดภัยและข้อจำกัด

- ชื่อและข้อมูลจาก Drive แสดงด้วย `textContent` ไม่แทรกเป็น HTML ลิงก์ภายนอกตรวจ protocol/host และใช้ `noopener noreferrer`
- Backend ตรวจว่าโฟลเดอร์อยู่ใต้หมวดที่ค้นพบจริงก่อนอ่าน ป้องกันการส่ง ID เพื่ออ่านโฟลเดอร์อื่นของเจ้าของสคริปต์
- สถานะการแบ่งหน้าเก็บชั่วคราวใน CacheService ไม่ใช่ฐานข้อมูลรายการไฟล์ หากหมดอายุให้เริ่มโหลดโฟลเดอร์หรือค้นหาใหม่
- หากข้อมูลเปลี่ยนระหว่างแบ่งหน้า ให้รีเฟรชหรือค้นหาใหม่เพื่ออ่านโครงสร้างปัจจุบัน
- โฟลเดอร์ชื่อหมวดซ้ำหรือหายจะแสดงปัญหา ไม่สุ่มเลือกโฟลเดอร์หนึ่งหรือแสดงข้อมูลจำลองแทน
- ทางลัด Google Drive แสดงเป็นไฟล์ทางลัด ไม่เดินตามทางลัดออกไปค้นหาโฟลเดอร์เป้าหมาย
- แอปเปิดเผยรายการหลักฐานใน 7 หมวดแก่ผู้ที่เข้าถึง Web App ตามการตั้งค่า deployment การเปิดตัวไฟล์ยังขึ้นกับสิทธิ์แชร์ของไฟล์นั้นใน Drive
- ไม่มีการเปลี่ยน WordPress หรือสิทธิ์แชร์ไฟล์ใน Drive

## ตรวจสอบและ push

สถานะตรวจสอบ: syntax/DOM, manifest โลโก้และภาพอาคารต้นฉบับผ่านเมื่อ 18 กันยายน 2569 ตรวจภาพหน้าแรกที่เว็บส่งกลับแล้วตรงกับ PNG ที่ผู้ใช้ส่งมาทุกไบต์
ชุดทดสอบเต็มเมื่อ 17 กันยายนผ่าน 51 ข้อ (backend 23 / frontend 28) รอบเปลี่ยนภาพวันที่ 18 กันยายนทดสอบ backend อีกครั้งผ่าน 23 ข้อ รวมการอนุญาตให้ include ภาพหน้าแรก ไม่ได้เปลี่ยน JavaScript ฝั่งผู้ใช้
การค้นหาและแบ่งหน้า ขอบเขตการอ่านไฟล์ ลิงก์ตรง ประวัติการนำทาง Clipboard
ตัวอ่าน PDF/รูปภาพ การซ่อนไฟล์ Word และแกลเลอรีหลายรูป รวมการโหลดต่อโดยรักษาเฟรมเดิม การรีเฟรช และโฟลเดอร์ที่มีไฟล์หลายชนิด

การทดสอบเพิ่มเติมครอบคลุมเมนูด้านซ้าย ประวัติย้อนกลับ/เดินหน้า ลิงก์แบบเปิดแท็บใหม่ หมวดที่ไม่พร้อมใช้งาน ข้อมูลแนะนำทั้ง 7 หมวด การซ่อนส่วนแนะนำในโฟลเดอร์ย่อย การโหลดเมนูแยกจากเอกสาร การลองใหม่ การป้องกันข้อมูลเก่าทับหน้าใหม่ และการแสดงกรอบว่างสำหรับกราฟเฉพาะหน้าแรก

เผยแพร่ล่าสุดเป็นเวอร์ชัน 16 เมื่อ 18 กันยายน 2569 บน URL เดิม เปลี่ยนภาพอาคารแบบ SVG ด้านขวาของแบนเนอร์หน้าแรกเป็น “รูป green office.png” ที่ผู้ใช้ส่งมา แสดงภาพเต็มด้วย `object-fit: contain` และปรับขนาดตามหน้าจอ โดยคงกล่องสีขาวและกรอบว่างสำหรับกราฟการใช้พลังงาน
เพิ่ม `hero-image.html` ที่สร้างจาก `assets/images/green-office-building.png` ด้วย `scripts/build-hero-image.cjs` และเพิ่มไฟล์นี้ในรายการ include ที่อนุญาตกับ `.claspignore` ภาพต้นฉบับขนาด 3,144,054 ไบต์ถูกฝังในหน้าเว็บโดยไม่แปลงไฟล์ จึงเพิ่มขนาดข้อมูลหน้าแรกตามขนาดภาพ
ตรวจและสำรองโค้ดบนเซิร์ฟเวอร์ที่ `.local/remote-before-v16-20260918/` แล้วตรงกับเวอร์ชัน 15 คำสั่งอัปเดต deployment ยืนยันเวอร์ชัน 16 สำเร็จ
ดาวน์โหลดเวอร์ชัน 16 กลับมาตรวจแล้ว ไฟล์แอปที่มีเนื้อหาทั้ง 10 ไฟล์ตรงกับไฟล์ในเครื่อง (`SheetService.gs` เป็นไฟล์ว่างที่ clasp ไม่เขียนลงดิสก์ขณะ pull)
ตรวจ HTTP `/exec` เมื่อ 18 กันยายนได้ 200 พร้อมภาพ PNG ขนาด 1536 × 1024 ที่ตรงกับต้นฉบับทุกไบต์ ไม่พบ SVG อาคารเดิม และ CSS ตรงกับไฟล์ในเครื่องหลังปรับคอมเมนต์และช่องว่างที่ Apps Script เปลี่ยนขณะส่งหน้าเว็บ
หลักฐานอยู่ใน `.local/live-v16-verification.json` และ `.local/deployed-v16-20260918/` ส่วนการตรวจกล่องสีขาวและขนาดตัวอักษรก่อนหน้าอยู่ใน `.local/white-card-review-20260918.json` และ `.local/readability-review-20260917.json`
การตรวจ HTTP ยืนยันเฉพาะ HTML/โค้ดที่เซิร์ฟเวอร์ส่ง ยังไม่ใช่การทดสอบกดใช้งานหรือสิทธิ์เปิด PDF/รูปภาพจริง
เซสชันวันที่ 18 กันยายนไม่มีเบราว์เซอร์เชื่อมต่อ จึงยังไม่ได้ตรวจภาพหน้าจอ การจัดหน้าจริง และการกดใช้งานจริง

ตรวจปัญหาแชร์ลิงก์วันที่ 16 กันยายน: การขอหน้าเว็บโดยไม่ส่งบัญชี Google ไปด้วยที่ `/macros/s/.../exec` ได้ HTTP 200 พร้อมโค้ดแอป แต่รูปแบบ `/macros/u/1/s/.../exec` ที่ปรากฏในภาพผู้ใช้ได้ HTTP 404 ก่อนถึงหน้าแอป ข้อสังเกตนี้สอดคล้องกับปัญหาหลายบัญชี แต่ยังไม่ได้ทดสอบเซสชันที่ลงชื่อเข้าใช้ของผู้ใช้โดยตรง
ให้ใช้ลิงก์มาตรฐานจากปุ่มคัดลอกลิงก์ และหากเปิดไม่ได้ ให้ลองหน้าต่างไม่ระบุตัวตน (Ctrl+Shift+N) โดยยังไม่ลงชื่อเข้าใช้ หรือใช้โปรไฟล์ที่มีบัญชี Google เดียว ตาม [คำแนะนำ Google เรื่องหลายบัญชี](https://developers.google.com/apps-script/guides/support/troubleshooting#issues_with_multiple_google_accounts)
กรณีเข้าเว็บได้แต่ตัวอย่างเอกสารขอสิทธิ์ ให้ตรวจสิทธิ์ไฟล์ใน Drive แยกจากสิทธิ์เข้า Web App

เปิดเว็บที่เผยแพร่: [Green Office ENVI 2569](https://script.google.com/macros/s/AKfycby1IpgVjvRZH8eEoTXMnybK2L7QL4_fcBw5YVrEfQePFjuJWBydQQ7oK-8FM8i9zevm/exec)

## ทดสอบและ Deploy เป็น Web App

1. เปิด Apps Script IDE ด้วยคำสั่งต่อไปนี้ (clasp 3.4.1 ไม่มีคำสั่ง `clasp open`):

   ```powershell
   clasp.cmd open-script
   ```

2. ใช้บัญชีที่อ่าน Root folder ได้ เลือกฟังก์ชัน `getDashboardData` แล้วกด **Run** และอนุญาตสิทธิ์อ่าน Drive หากระบบร้องขอ ตรวจว่า Execution log ไม่มีข้อผิดพลาด
3. ไปที่ **Deploy → Test deployments → Web app** เปิด URL `/dev` เพื่อทดสอบโค้ดล่าสุด ผู้ทดสอบต้องมีสิทธิ์แก้ไขสคริปต์
4. เมื่อตรวจแล้ว ไปที่ **Deploy → New deployment → Select type → Web app** ตั้งชื่อเวอร์ชัน เช่น `Green Office ENVI 2569 — V1`
5. เลือก **Execute as: Me** โดยบัญชีนี้ต้องอ่านโฟลเดอร์หลักและหลักฐานได้
6. เลือก **Who has access: Anyone** หากต้องการหน้าเว็บสาธารณะที่ไม่บังคับลงชื่อเข้าใช้ Google ตัวเลือกนี้ขึ้นกับนโยบาย Google Workspace ของมหาวิทยาลัย หากไม่มีต้องใช้ตัวเลือกที่ผู้ดูแลอนุญาตหรือปรึกษาผู้ดูแลโดเมน
7. กด **Deploy** อนุญาตสิทธิ์ตามที่ระบบแสดง แล้วใช้ URL ลงท้าย `/exec`

หากมี Web App deployment อยู่แล้ว ให้อัปเดตผ่าน **Deploy → Manage deployments → Edit → Version: New version → Deploy** เพื่อรักษา URL เดิม การ `clasp.cmd push` เปลี่ยนโค้ดในโปรเจกต์ แต่ไม่อัปเดตเวอร์ชันที่เผยแพร่แล้วให้อัตโนมัติ

อ้างอิง: [Google Apps Script — Web apps และการทดสอบ /dev](https://developers.google.com/apps-script/guides/web), [การจัดการ deployment](https://developers.google.com/apps-script/concepts/deployments)

## ตรวจรับบน Web App จริง

1. หน้าแรกแสดงชื่อคณะ ปี 2569 สรุป 7/24/65 เมนูครบทั้ง 7 หมวดด้านซ้าย และกรอบว่างสำหรับกราฟการใช้พลังงานตรงกลาง กรอบนี้ต้องซ่อนเมื่อเปิดหมวด โฟลเดอร์ เอกสาร หรือผลการค้นหา
2. เปิดหมวด 1 → คำสั่งคณะทำงาน ตรวจ breadcrumb, PDF ที่แสดงอัตโนมัติ, การสลับรูปภาพ, ปุ่มก่อนหน้า/ถัดไป และปุ่มขยาย โดยยังอยู่ในหน้าเว็บ
3. เปิดหมวด 7 ตรวจตัวอย่าง HEIC, ปุ่มแสดง/ซ่อนไฟล์ Word และหมวดที่ยังว่าง
4. ค้นหา `คำสั่ง` และ `HEIC` ตรวจผลทั้งโฟลเดอร์และไฟล์ พร้อมกดค้นหาต่อหากยังไม่ครบ
5. เพิ่มไฟล์ทดสอบในโฟลเดอร์หลักฐานแล้วกดรีเฟรช ต้องอ่านเจอโดยไม่ push ใหม่
6. ทดสอบจากมือถือ และทดสอบผู้ชมตามสิทธิ์ deployment รวมถึงสิทธิ์เปิดไฟล์ Drive
7. คัดลอกลิงก์หมวด โฟลเดอร์ย่อย และหน้าเอกสารไปเปิดแท็บใหม่ ต้องเปิดหน้าที่ระบุได้ รวมถึงรีเฟรชและใช้ปุ่มย้อนกลับ/เดินหน้า
8. ตรวจโลโก้ที่ส่วนหัวและปุ่มคัดลอกลิงก์ ทั้งกรณี Clipboard ทำงานและกรณีแสดงช่องให้คัดลอกเอง
